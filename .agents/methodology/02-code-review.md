# 段階2: コードレビュー

観点の本体は `.agents/checklists/` にある（単一の情報源）。ここには選び方とレビューの原則だけを書く。

## チェックリストの選び方（`va.py` が自動で行う）

- `general`（`tags: [always]`）は常に適用
- ファイル要約の `tags` とチェックリストの `tags` が1つでも一致すれば適用
- `kind: entry` またはパス名が入口らしいファイルには `http-input` を足す
- `langs` が `any` か、ファイルの言語に一致するものだけ

## 原則（プロンプト `prompts/tasks/review-file.md` に反映済み）

- 入口から危険な操作（sink）へ、攻撃者が制御できる値が届く経路を説明できるものだけを候補にする
- 行番号を必ず付ける。チャンクの範囲外・許可カテゴリ外の候補はスクリプトが捨て、`dropped` として記録する
  （`dropped` が多いモデルは指示に従えていないので、retrospective がモデルプロファイルに反映する）
- 何も無いことは正しい結果

## 観点を増やしたいとき

新しいチェックリストを1ファイル追加する（10項目以内）。タグの語彙を増やす場合は
`scripts/va.py` の `TAGS` と `checklists/README.md` を同時に更新し、`python3 scripts/va.py validate` を通す。
